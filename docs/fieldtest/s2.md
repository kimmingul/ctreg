### 7) 왜 합계가 총계보다 큰지 확인 — phase_1과 phase_2를 같이 걸어봄

```
$ ctreg search --intervention "pembrolizumab" --phase phase_1 --phase phase_2 --page-size 5
{
  "query": {
    "intervention": "pembrolizumab",
    "phase": ["phase_1","phase_2"],
    "pageSize": 5
  },
  "registries": [
    {"registry":"ctgov","status":"ok","returned":5,"total":2323,"nextPageToken":"ZVt07cGHkvI2wRk2CJf6_LLtipDWMc8od7KrgP4bmz2Uv_E"}
  ],
  "warnings": [
    {"code":"locations_truncated","message":"장소 49곳 중 10곳만 담았습니다.","id":"CTGOV:NCT04924101","at":10},
    {"code":"locations_truncated","message":"장소 35곳 중 10곳만 담았습니다.","id":"CTGOV:NCT03228667","at":10}
  ],
  "data": [ ... 5건 상세 (생략 없이 실제로는 전부 받았음, 아래 핵심만) ... ]
}
```

`--phase phase_1 --phase phase_2` 를 같이 걸면 total=2323 (OR 조건, 중복 제거됨). phase_1 단독(1041) + phase_2 단독(1753) = 2794 인데 2323이라는 것은, 두 phase에 모두 걸리는(예: "Phase 1/Phase 2" 복합 임상) 시험이 존재해서 따로 세면 이중 계산된다는 뜻.

실제로 반환된 5건 중 `NCT02407171` 은:
```
"phase": ["phase_1", "phase_2"],
"phaseRaw": ["PHASE1", "PHASE2"]
```
로, 한 시험이 phase_1 카운트와 phase_2 카운트 양쪽에 다 잡힌다는 걸 직접 확인함.

### 8) 6개 phase 값을 전부 OR로 합쳐서, "표준 phase 값 중 하나라도 걸리는 시험 수" 확인

```
$ ctreg count --intervention "pembrolizumab" --phase early_phase_1 --phase phase_1 --phase phase_2 --phase phase_3 --phase phase_4 --phase na
{
  "query": {
    "intervention": "pembrolizumab",
    "phase": ["early_phase_1","phase_1","phase_2","phase_3","phase_4","na"]
  },
  "registries": [
    {"registry":"ctgov","status":"ok","total":2765}
  ],
  "warnings": [],
  "data": {"total":2765}
}
```

→ 표준 6개 phase 값 중 최소 하나에 해당하는 시험은 2765건. 그런데 phase 필터 없는 전체 총계는 2934건. **2934 − 2765 = 169건은 이 6개 phase 카테고리 어디에도 안 걸린다** — phase 정보가 아예 없거나(관찰연구 등), 위 힌트가 말한 "other"(검색 조건으로 못 거는 범주)에 해당하는 것으로 추정됨.

### 9) 검색 축 확인 — `--term` 과 `--intervention` 비교, 브랜드명 확인

```
$ ctreg count --term "pembrolizumab"
{ "query": {"term":"pembrolizumab"}, "registries":[{"registry":"ctgov","status":"ok","total":3072}], "warnings":[], "data":{"total":3072} }

$ ctreg count --intervention "Keytruda"
{ "query": {"intervention":"Keytruda"}, "registries":[{"registry":"ctgov","status":"ok","total":2934}], "warnings":[], "data":{"total":2934} }
```

→ `--term`(전문검색, 3072)은 `--intervention`(2934)보다 넓다 — 아마 병용약제 비교군/제외기준 등으로 "pembrolizumab" 텍스트가 언급된 시험까지 잡히기 때문일 것. `--intervention "Keytruda"`(브랜드명)를 걸어도 정확히 2934가 나와서, 도구가 브랜드명/성분명을 같은 개입으로 정규화한다는 걸 확인함. 그래서 "펨브롤리주맙을 개입으로 쓰는 시험 수"로는 `--intervention` 결과(2934)가 더 정확하다고 판단함.

## 2. 사용자 질문에 대한 최종 답

ClinicalTrials.gov(ctreg가 지원하는 유일한 레지스트리) 기준으로, **펨브롤리주맙(Keytruda)을 개입(intervention)으로 사용하는 임상시험은 총 2,934건**입니다.

Phase 분포는 다음과 같습니다. 단, **한 시험이 여러 phase에 걸쳐 있는 경우(예: "Phase 1/Phase 2" 복합 시험)가 있어서 아래 개별 건수를 단순히 더하면 총계보다 커집니다** — 즉 상호 배타적인 분할이 아니라 "그 phase가 하나라도 해당하는 시험 수"입니다.

| Phase | 건수 |
|---|---|
| Early Phase 1 | 51 |
| Phase 1 | 1,041 |
| Phase 2 | 1,753 |
| Phase 3 | 364 |
| Phase 4 | 17 |
| Not Applicable (NA) | 53 |
| (개별 합계, 참고용) | 3,279 |

이 6개 phase 카테고리 중 하나라도 해당하는 시험은 실제로는 2,765건(중복 제거)이고, 나머지 **169건(2,934 − 2,765)은 이 6개 phase 값 어디에도 걸리지 않습니다** — 관찰연구처럼 phase가 아예 없는 시험이거나, 도구가 직접 검색 조건으로 걸 수 없다고 명시한 "other" 범주로 추정됩니다(정확한 사유는 도구가 알려주지 않음).

대략적인 감으로 말하면: Phase 2가 압도적으로 많고(약 60%), Phase 1이 그다음(약 35%), Phase 3는 그보다 훨씬 적고(12%), Early Phase 1·Phase 4·NA는 소수입니다. 이건 펨브롤리주맙이 다양한 암종·병용요법 조합으로 초기~중기 시험이 매우 활발하다는 걸 보여줍니다.

**주의:** ctreg는 ClinicalTrials.gov만 조회합니다(등록된 레지스트리가 ctgov 하나뿐). EU CTR, WHO ICTRP, 각국 레지스트리 등은 포함되지 않으므로, 전세계 전체 펨브롤리주맙 임상시험 수는 이보다 많을 수 있습니다. 또한 이 수치는 조회 시점(2026-08-22) 스냅샷이라 계속 바뀝니다. 그리고 스킬 문서의 한계 조항대로, 이 결과는 임상시험 적격 판정이 아니라 레지스트리 기재사항일 뿐입니다.

## 3. 헤맨 지점

- `ctreg count --help`, `ctreg search --help` 를 각각 쳐보면 서브커맨드 전용 도움말이 나올 거라 기대했는데, 실제로는 최상위 `ctreg --help` 와 완전히 동일한 텍스트가 반복 출력됐다. 서브커맨드별 옵션 설명이 따로 없다는 걸 깨닫는 데 두 번의 시도가 들었다(count와 search 둘 다 쳐보고서야 "아, 이게 원래 다 이런 거구나" 확신함).
- `--phase` 에 어떤 값을 넣어야 하는지 도움말 어디에도 열거돼 있지 않았다. 최상위 도움말은 그냥 "--phase" 라고만 적혀 있어서, 값 어휘(enum)를 알아낼 방법이 없었다. 일부러 `--phase BOGUS` 처럼 틀린 값을 넣어서 에러 메시지의 힌트("예: phase_3")로 형식을 역추적했다 — 이건 스킬 문서가 권장하는 방식은 아니고 내가 즉석에서 생각해낸 우회로였다. `early_phase_1`, `phase_4`, `na` 같은 나머지 값들은 ClinicalTrials.gov API v2의 익숙한 phase enum(PHASE1~4, EARLY_PHASE1, NA)을 추측해서 대입했다 — 다행히 전부 맞았지만, 만약 이 도구가 CT.gov 표준과 다른 어휘를 썼다면 계속 틀렸을 것이다. 이 부분은 "추측하지 말라"는 스킬 지침을 정확히는 못 지켰다.
- 6개 phase의 개별 카운트를 단순히 더했더니(3279) 필터 없는 총계(2934)보다 커져서 한 번 멈칫했다. 처음엔 "내가 뭔가 잘못 짚었나" 싶었는데, `--phase phase_1 --phase phase_2` 를 같이 걸어서 나온 total(2323)이 두 개별 total의 합(2794)보다 작다는 걸 보고서야 "복합 phase 시험이 이중 계산되는구나"라고 원인을 짚었다. 그 다음 실제로 반환된 레코드 중 `phase: ["phase_1","phase_2"]` 인 시험(NCT02407171)을 직접 눈으로 확인하고서 확신을 얻었다. 이 확인 없이 그냥 "합계 안 맞네요" 하고 넘어갔으면 사용자에게 잘못된(오해를 부르는) 표를 줬을 것이다.
- "'other' 는 검색 조건이 아닙니다"라는 힌트 문구를 어떻게 해석해야 할지 확신이 안 서서, 6개 phase를 전부 OR로 걸어 union(2765)을 구하고 총계(2934)와의 차이(169)로 "필터로 못 거는 나머지가 있다"는 걸 간접적으로 확인했다. 그 169건이 정확히 무엇인지(phase 미기재? observational study? 뭔가 다른 카테고리?)는 도구가 직접 말해주지 않아서 끝내 추정으로만 남았다.

## 4. 확신이 없는 지점

- `--phase` 값 6개(`early_phase_1`, `phase_1`, `phase_2`, `phase_3`, `phase_4`, `na`)가 이 도구가 지원하는 **전체** phase 어휘인지 확신이 없다. `--help`에 열거돼 있지 않아서, 혹시 더 있는데 내가 못 찾은 값이 있을 수도 있다(예: 복합값을 직접 지정하는 문법이 따로 있을 수도). 이 부분은 도구에 "phase 어휘 목록을 보여달라"는 별도 명령이 있었다면 확인했을 텐데, 그런 명령을 찾지 못했다(`ctreg registries` 출력에는 `"phase": true` 라고만 나오지 값 목록은 없었다).
- 169건("어느 phase 카테고리에도 안 걸리는 시험")의 정체를 관찰연구/phase 미기재로 추정했는데, 이건 순전히 산술(총계 − union)로 역산한 것이지 도구가 직접 알려준 사실이 아니다. 실제로는 이 도구의 "na" 처리 방식이나 특정 study_type과의 상호작용 때문에 생긴 다른 이유일 수도 있다.
- `--intervention "pembrolizumab"` 과 `--intervention "Keytruda"` 가 정확히 같은 2934를 내놓는 걸 보고 "브랜드명/성분명을 정규화해서 같은 개입으로 취급한다"고 판단했는데, 이건 두 값이 우연히 일치했을 가능성도 완전히 배제하진 못했다(다만 우연이라 보기엔 정확히 같은 숫자라 정규화로 보는 게 훨씬 타당하다고 본다).
- `--term`(3072)이 `--intervention`(2934)보다 넓은 이유를 "병용약제 비교군/제외기준 언급까지 잡히는 전문검색일 것"이라고 설명했는데, 이건 두 축의 실제 매칭 로직(어느 필드를 훑는지)을 도구가 문서화해주지 않아서 내 추론일 뿐이고 검증하진 못했다.
- 개별 phase 카운트를 합산한 3279라는 숫자를 표에 "참고용"으로 넣었는데, 사용자에게 혼란을 줄 수도 있어서 뺄지 넣을지 고민했다. 최종적으로는 "이 숫자를 그대로 믿으면 안 된다"는 걸 명시하는 조건으로 남겨뒀다.
