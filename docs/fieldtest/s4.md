```
$ export PATH=/tmp/ctreg-bin:$PATH

```

## 2. 사용자 질문에 대한 최종 답

세 개 ID 중 두 개는 ClinicalTrials.gov에서 찾았고, 하나는 존재하지 않는 등록번호였습니다.

**1) NCT04280705 — Adaptive COVID-19 Treatment Trial (ACTT)**
- 정식명: A Multicenter, Adaptive, Randomized Blinded Controlled Trial of the Safety and Efficacy of Investigational Therapeutics for the Treatment of COVID-19 in Hospitalized Adults
- 상태: 완료(Completed) · Phase 3 · 중재연구(Interventional)
- 대상 질환: COVID-19
- 중재: Remdesivir(약물) vs Placebo
- 주관: National Institute of Allergy and Infectious Diseases (NIAID)
- 등록 인원: 1,062명 (실제)
- 기간: 2020-02-21 ~ 2020-05-21 (1차 완료·전체 완료 동일), 최초 게시 2020-02-21, 최종 업데이트 2022-03-14
- 장소: 총 60곳 중 10곳만 반환됨 (도구가 자체적으로 잘라서 반환 — 아래 경고 참고). 반환된 곳은 앨라배마 버밍엄, 캘리포니아 여러 곳(라호이아, LA, 오렌지, 팔로알토, 새크라멘토, 샌디에이고, 샌프란시스코, 스탠퍼드, 웨스트할리우드) 등.
- 결과 보고 여부: 있음 (hasResults: true) — 다만 이번 조회는 `get`만 실행했고 결과/이상반응 상세(`ctreg results`)는 조회하지 않았습니다.

**2) NCT00000102 — Congenital Adrenal Hyperplasia: Calcium Channels as Therapeutic Targets**
- 상태: 완료(Completed) · Phase 1/2 · 중재연구(Interventional)
- 대상 질환: Congenital Adrenal Hyperplasia (선천성 부신과형성)
- 중재: Nifedipine(약물)
- 주관: National Center for Research Resources (NCRR)
- 교차 ID: NIH M01RR001070
- 장소: Medical University of South Carolina (Charleston, SC) 1곳
- 최초 게시: 1999-11-04, 최종 업데이트: 2005-06-24
- 결과 보고 여부: 없음 (hasResults: false)

**3) NCT99999999 — 찾을 수 없음**
- ClinicalTrials.gov에 존재하지 않는 등록번호입니다 (`not_found` 경고). 오타이거나 실제로 등록되지 않은 번호로 보입니다. 정확한 NCT 번호를 다시 확인해 주세요.

**경고 요약 (읽어야 할 것):**
- `locations_truncated`: NCT04280705는 실제 장소가 60곳인데 이 도구는 10곳만 담아 반환했습니다. 전체 장소 목록이 필요하면 이 결과를 "전체"로 오해하면 안 되고, 페이지네이션/추가 옵션으로 더 가져와야 합니다 (이번 조회에서는 시도하지 않았습니다).
- `not_found`: NCT99999999는 애초에 없는 시험입니다.

**한계 고지**: 이 정보는 임상시험 등록 데이터일 뿐 적격 판정이 아닙니다. 참여 가능 여부는 별도 스크리닝이 필요합니다.

## 3. 헤맨 지점

- 특별히 크게 헤매지는 않았습니다. `--help` → `registries` → `get`으로 스킬이 지시한 순서를 그대로 따랐고 첫 시도에서 원하는 결과를 얻었습니다.
- 다만 `get` 결과를 받고 나서 "정말 이게 다인가?" 하고 하위 명령 전용 도움말(`ctreg get --help`)이 따로 있는지 확인해봤습니다 — 있으면 exit code 5(부분 실패)가 정확히 언제 뜨는지 더 자세히 설명해줄까 기대했기 때문입니다. 결과는 최상위 도움말과 완전히 동일한 화면이 다시 나와서, 이 도구는 하위 명령별 도움말을 따로 두지 않는다는 걸 확인만 하고 끝났습니다 (헛수고였지만 짧게 끝남).
- `ctreg results NCT04280705`까지 불러서 결과/이상반응 상세를 확인할지 고민했습니다. 사용자가 "정리해주세요"라고만 했고 결과 상세를 명시적으로 요청하지 않았다고 판단해 `get`에서 멈췄습니다 — 이 판단이 맞는지는 100% 확신이 없습니다 (4번 참고).

## 4. 확신이 없는 지점

- **exit code 0과 경고의 관계**: `--help`에 따르면 exit 5는 "부분 실패"인데, 이번 `get` 호출은 3개 ID 중 1개가 `not_found`였고 1개는 `locations_truncated` 경고까지 있었는데도 exit code는 0(정상)이었습니다. "부분 실패"가 정확히 어떤 상황에서 5로 뜨는지 (예: 레지스트리 자체가 응답 안 할 때만? 아니면 배치 조회에서 일부 ID가 없어도 "찾은 것들은 정상 반환했으니 0"이라는 설계인지) 도구 스스로는 설명해주지 않았습니다. 소스 코드를 볼 수 없는 제약 때문에 이 부분은 관찰한 사실(=0이 나왔다)만 확인했고, 왜 그런지는 추측입니다.
- **hasResults: true인 NCT04280705에 대해 `ctreg results`를 불러야 했는지**: 사용자는 "정보를 정리해달라"고만 했지 결과/이상반응을 명시적으로 요구하지 않았습니다. 스킬 설명에는 "시험이 결과를 보고했는지 확인"이 이 도구의 대표 용례로 나와 있어서, hasResults만 언급하고 상세 결과는 안 판 것이 사용자 기대에 못 미칠 수도 있다고 생각합니다. 애매해서 일단 범위를 좁게 잡았습니다.
- **NCT04280705의 장소 60곳 중 10곳만 반환된 것을 더 채울 방법**: `--page-size`나 페이지네이션 옵션이 `get`에도 적용되는지, 아니면 `search`에만 적용되는지 `--help`만으로는 명확하지 않았습니다. 직접 `--page-size` 옵션을 `get`에 붙여서 시도해보지는 않았습니다 — 실패 시 exit 2(사용법 오류)가 뜰지, 조용히 무시될지 확신이 없어 이번 작업 범위에서는 시도하지 않았습니다.
